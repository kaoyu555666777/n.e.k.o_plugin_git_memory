# Git 记忆同步 - 快速开始

用 GitPython 把 N.E.K.O 的 `memory` 目录备份到 GitHub / GitLab / Gitee 的私有仓库，支持手动同步与每 5 / 10 / 30 / 60 分钟自动同步。全部配置都在插件面板里完成。

> 默认同步的目录是「软件存储目录 / memory」，也就是你平时存放记忆的地方。如果你的存储目录是自定义的，插件会自动跟随；也可以直接在面板里填写别的路径。


## 一、先确认 Git 可用

打开插件面板时，插件会立刻检查三项内容：Git 命令行、GitPython 依赖、`memory` 目录的仓库状态。

- **检测通过** — 「Git 环境」卡片显示绿色「可用」，并列出 `git --version` 的版本号与 Git 路径。
- **没有检测到 Git** — 面板会自动弹出安装提示窗口，并提供：
  - **Windows** — Git for Windows 官方下载页、最新安装包、`winget install --id Git.Git -e --source winget`、`scoop install git`
  - **macOS** — 官方下载说明、Homebrew 公式、`xcode-select --install`、`brew install git`
  - **Linux** — 插件读取 `/etc/os-release`，按发行版给出对应命令（`apt` / `dnf` / `zypper` / `pacman` / `apk` / `emerge` / `nix` / `xbps` / `eopkg`），并附带常见发行版的备用命令
  - 每条命令右侧都有「复制」按钮，可以直接粘到终端里执行

装好之后**重启 N.E.K.O**（让新的 PATH 生效），回到面板点击「重新检测」。检测通过前，自动同步与手动同步都不会执行，也不会产生任何 Git 操作。


## 二、把 memory 目录变成 Git 仓库

在「记忆仓库」卡片里点击「初始化仓库」：

1. 插件在 `memory` 目录执行 `git init`（默认分支 `main`，可在设置里改）。
2. 按当前的 `.gitignore` 预设写入忽略规则，默认忽略 `*.tmp`、`*.log`、`__pycache__/` 等临时文件。
3. 保存你填写的提交用户名与邮箱，作为该仓库的 `user.name` / `user.email`；留空则跟随 Git 全局配置。

初始化只会写入 `.git` 与 `.gitignore`，不会改动任何记忆文件。如果目录里已经存在 `.git`，插件会直接读取现有仓库，不会覆盖历史。


## 三、选择平台并配置访问令牌

在「账号与远端仓库」卡片里：

1. 选择 **GitHub / GitLab / Gitee** 之一。
2. 点击「创建访问令牌」，浏览器会打开对应平台带好范围的令牌创建页：
   - **GitHub** — 经典令牌勾选 `repo`；细粒度令牌需要 Contents 读写，创建仓库还需要 Administration 写权限。
   - **GitLab** — 个人访问令牌勾选 `api`。
   - **Gitee** — 私人令牌勾选 `projects`（仓库读写）。
3. 把令牌粘贴到「访问令牌」输入框，点击「校验并保存令牌」。

令牌会先联网校验账号，校验通过后**加密保存在插件的私有数据目录**里，不会写入 `memory` 目录，也不会出现在日志或面板回显中。自建 GitLab / Gitee 可以在「自建站点地址」里填自己的域名。


## 四、关联仓库

两种方式任选其一：

- **关联已有仓库** — 点「读取仓库列表」（可以先用搜索框过滤），在表格里选中一个仓库，再点「关联选中仓库并同步」。插件会把它设置为 `origin`，并立刻提交、拉取、推送一次。
- **创建私有仓库** — 填写仓库名称与描述，保持「创建为私有仓库」打开，点「创建私有仓库并关联」。仓库会创建在你的账号下，默认私有，随后自动关联并同步。

关联完成后，「记忆仓库」卡片会显示当前分支、远端地址、待同步改动数量与最近一次提交。点「打开远端仓库」可以直接在浏览器里查看，点「打开记忆目录」会打开本地文件夹。

需要断开时点「解除远端关联」：只会删除仓库上的远端配置，本地文件与提交历史都会保留。


## 五、同步方式

**手动同步** — 面板上的「立即同步」按钮，或直接让 NEKO 调用「同步记忆到 Git」入口。

**自动同步** — 在「同步设置」里打开开关，并选择间隔：**5 / 10 / 30 / 60 分钟**。插件运行期间每分钟检查一次是否到点，到点就执行一次同步；面板会显示上次同步时间与下次预计时间。

每一次同步依次做三件事：

1. **提交** — 把 `memory` 目录的改动 `git add -A` 并按提交信息模板生成提交（模板支持 `{timestamp}`、`{date}`、`{time}`、`{hostname}`、`{count}`）。
2. **拉取**（可在设置里关闭）— `git fetch` 远端分支；远端有更新时按冲突策略合并。
3. **推送** — `git push` 到已关联的远端分支；首次推送会自动设置上游分支。

同步成功后，面板的「步骤」表格会逐条列出 commit / pull / push 的结果；没有改动时会提示「没有需要同步的改动」。手动同步与自动同步共用一把锁，同一时刻只会执行一个任务。


## 六、Git 设置

「Git 设置」卡片里的内容都可以随时调整，点「保存 Git 设置」后立即生效：

- **分支** — 同步使用的分支名，默认 `main`。
- **远端名称** — 默认 `origin`。
- **提交用户名 / 邮箱** — 写入仓库级 Git 配置，留空则使用全局配置。
- **提交信息模板** — 默认 `chore(memory): sync {timestamp}`。
- **冲突处理** — `ours` 保留本地记忆，或 `abort` 中止同步并提示（默认 `ours`）。
- **网络代理** — 留空跟随系统代理环境变量。
- **推送前先拉取远端** — 关闭后只提交并推送本地改动。
- **自动同步失败时提醒我** — 失败时通过 HUD 推送一条提醒。
- **.gitignore 预设与追加规则** — 预设 `default` / `minimal` / `none`，下面是当前生效规则的实时预览。


## 七、常见问题

- **提示未安装 Git** — 按弹窗里的链接或命令安装，重启 N.E.K.O 后点「重新检测」。
- **读取仓库列表失败 / 权限不足** — 令牌范围不够。GitHub 勾 `repo`，GitLab 勾 `api`，Gitee 勾 `projects`，然后重新校验保存。
- **连接超时** — 在「Git 设置」里填写代理地址（例如 `http://127.0.0.1:7890`），或检查系统代理环境变量。
- **推送被拒绝 / 历史分叉** — 把冲突处理设为 `ours` 后重试一次，或先在本地手动处理分叉历史。
- **想在别的目录同步** — 面板默认跟随软件存储目录；如需固定路径，可在插件配置的 `[git_memory]` 段里填写 `memory_dir`。
- **想临时停掉** — 关闭自动同步开关即可；已关联的远端与本地仓库都会保留。


## 八、数据与隐私

- 访问令牌保存在插件的私有数据目录（加密存储），不随记忆内容一起同步。
- `memory` 目录里除了 `.git`、`.gitignore` 之外不会多出任何文件。
- 远端仓库默认私有，只有你自己能访问；建议不要改成公开仓库。
- NEKO 也可以直接调用插件入口「同步记忆到 Git」和「查看记忆同步状态」，无需打开面板。
